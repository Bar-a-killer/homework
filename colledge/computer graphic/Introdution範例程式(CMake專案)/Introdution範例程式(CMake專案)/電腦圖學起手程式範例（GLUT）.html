電腦圖學起手程式範例（GLUT）

本起手程式範例採用 freeglut 做為 OpenGL 的視窗管理工具，並已經搭配 glm、imgui 等相關實用套件、採用 C++ 17 為程式語言和使用 Cmake 來管理建置跨平臺之專案。

套件管理工具為 vcpkg，詳情可以查看 vcpkg 的 github 頁面 。

此套件管理工具為跨平台，Window、Linux 以及 MacOS 都可以使用，非常方便。

glm 是一個很好用的數學輔助工具，裡面已經定義好了向量和矩陣的相關基礎運算；imgui 則是一個實用的即時性互動 UI，不用過於複雜的程式碼就可以產生操作介面，Debug 非常好用！

對於 OpenGL 的一些背景介紹

OpenGL 是一個跨平臺的圖像API，裡面只有函式的規範與定義，其內部實作是由 GPU 製造商負責（例如：Nvidia 或 AMD）；而 glut 是一個跨平台來處理作業系統、I/O 和視窗管理的一個工具庫，最初也是為了簡單學習 OpenGL 設計的。

glut 基本上已經停止支援更新且版本過舊（v3.7 beta 可以追朔到 1998），所以後來出現了 freeglut ，是一個開源且目的就是為了取代 glut ，且裡面的 function 也基本上完全兼容 glut ，現在 freeglut 的穩定版為：3.2.1 （2019/09/23 release）。

glut / freeglut 都是採用 OpenGL 1.X 的函式，如果要使用到 2.X 的 function 就必須還要再引入 glew 庫，基本上老師會是以 glut 以及 OpenGL 1.X 為教學為主，並且會強調電腦圖學的基礎知識，並非程式；自從 OpenGL 3.X 發布之後，整個 OpenGL 的渲染流程（Graphics Pipeline）大改動，基本上整個架構與程式碼也變動許多，OpenGL 3.X 之後的版本稱為 Core Profile，也稱 Modern OpenGL Programing ，而 OpenGL 2.X 與之前的版本則被稱為 Legacy，基本上許多 官方文件 上都會寫說不建議學習。

基本上，如果對於電腦圖學有強大的興趣的話可以考慮直接學習使用 GLFW 或者 SDL 做為視窗管理工具，並使用 OpenGL 3.X 或者 4.X （兩個版本大同小異），雖然學習門檻比較高（需要了解 VAO、VBO、GLSL等），但相對不管是效能、彈性等都會比 glut 好很多，以下是一些很好用的參考網站：

  • 學習 Modern OpenGL （GLFW + glad + OpenGL 3.3）的好網站　LearnOpenGL：原文 簡中
  • 電腦圖學基礎知識：Song Ho Ahn
  • 線性代數可以看 3Blue1Brown

注意：如果使用 Qt 或是 SDL 做為底層框架，內部程式必須也要有使用到 OpenGL API，不可以只使用其框架的內建繪圖 function，這樣的作業是不會被接受的。

Vcpkg 安裝方式

注意事項：

  1. 使用 vcpkg 一定要特別安裝 Visual Studio 的英文語言包才能使用（就算IDE用別家的也是一樣要安裝）

  2. 小心防毒程式會誤判 vcpkg.exe 為病毒（經過實測 avast 會誤判），如果發生誤判記得將此程式設定白名單。

  3. 為了方便操作可以將 vcpkg 設定到環境變數 PATH 中。

  4. （如果是win10）安裝路徑建議選擇 C:\dev ，也是官方建議的安裝路徑；（如果是linux）可以自己定義路徑，例如安裝在 ~/repo 。

以下為安裝指令：

$ cd C:\dev
$ git clone https://github.com/microsoft/vcpkg
$ cd vcpkg
$ .\bootstrap-vcpkg.bat

// On Windows
$ vcpkg install freeglut glm imgui --triplet=x64-windows
$ vcpkg install imgui[glut-binding] imgui[opengl2-binding] --triplet=x64-windows --recurse
$ vcpkg integrate install

// On Linux (MacOS Maybe...)
$ vcpkg install freeglut glm imgui
$ vcpkg install "imgui[glut-binding]" "imgui[opengl2-binding]" --recurse

已經安裝過的套件就不用再安裝了。

CMake 建置方式

Visual Studio

基本上使用 Visual Studio 做為 IDE 會比較簡單，只要有輸入指令 vcpkg integrate install vcpkg 就會自動把相關的動態組態檔連結起來，不需要做其他動作就可以使用第三方也就是用 vcpkg 所安裝好的套件。

如果發生找不到標頭檔或是編譯連結出錯的情況，很有可能是因為 vcpkg 安裝 x64 版本，但編譯設定到 x86，記得編譯設定改為 x64 基本上問題就解決了。

PS: 使用 Visual Studio 開發，繳交作業或是使用 git 版控時請務必將 .vs 隱藏資料夾刪除，這個檔案單純只是 Visual Studio 的一些設定檔，是不必須而且 檔案很肥。

直接 CMake 指令編譯

如果以上編譯時出了甚麼差錯，基本上也可以先嘗試看看使用在終端機輸入指令的方式來進行編譯，語法如下：

$ cmake -B <path_to_build> -S <path_to_source> -DCMAKE_BUILD_TYPE=<build_type> -DCMAKE_TOOLCHAIN_FILE=<the_path_to_your_vcpkg_cmake>
$ cmake --build <dir>

第一行指令主要是告訴 CMake 你指定的建置路徑（-B <path_to_build>）、原始碼路徑（-S <path_to_source>）；-DCMAKE_BUILD_TYPE=<build_type> 則是說明想要的建置模式是 Debug 還是 Release，-DCMAKE_TOOLCHAIN_FILE=<the_path_to_your_vcpkg_cmake> 則是如果有使用到 vcpkg 所安裝的第三方套件，則一定要附上，這樣你的 CMake 才會知道要去哪裡找你所使用的套件。

如果你不清楚你的 vcpkg tool chain 路徑，可以嘗試輸入 vcpkg integrate install 指令即可顯示。

第一行指令是讓 CMake 產生快取，第二行還是真正的建置與編譯專案，其中路徑都是可以自己決定，有的人習慣 .\build、.\out、.\cmake-build-debug 等，都可以自己決定（但是 Debug 和Release 路徑一定要分開）。

例如可以這樣輸入：

// On Windows x64-debug
$ cmake -B .\out\debug -S . -DCMAKE_BUILD_TYPE=Debug -DCMAKE_TOOLCHAIN_FILE=C:\dev\vcpkg\scripts\buildsystems\vcpkg.cmake
$ cmake --build .\out\debug

// On Linux x64-release (記得要使用正斜線)
$ cmake -B ./build/release -S . -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=~/repo/vcpkg/scripts/buildsystems/vcpkg.cmake
$ cmake --build ./build/release

編譯好的應用程式就會在你所指定的 build 資料夾內。一般來說如果是使用 window 且有安裝過 Visual Studio 的話，預設編譯器都會是 MSVC（linux 的話的預設編譯器應該是 gcc）；而產生器 （Generators） 如果選擇是 Visual Studio 16 2019 的話，產生出來的建置方案會是很類似 Visual Studio 的專案格式，如果有安裝其他的產生器的話可以選擇其他，例如： ninja、NMake Makefiles 等等，詳情可以輸入 cmake --help 指令來查看。
