## d. 設計構想與演算法

### d.1 相機表示

以眼睛位置 `eye` 加上眼睛座標系的三個單位向量 Xe、Ye、Ze 表示相機，三個向量存放在 `u[3][3]` 中。

- Xe：相機的右方。
- Ye：相機的上方（view up vector）。
- Ze：相機的後方，所以實際觀看方向是 −Ze。

初始相機位置為 (25, 8, 60)，三軸方向與世界座標系相同。

繪圖時使用 `gluLookAt(eye, eye − Ze, Ye)` 產生視角矩陣。因為 focus 可以直接從 eye 與 Ze 算出來，所以不用另外存一個變數記錄。

### d.2 相機平移

Surge、Heave、Sway 本質上都是沿著相機的其中一個座標軸移動，因此三種操作共用 `cam_move()`。

每次將 eye 加上或減去對應的單位向量即可。

- Surge：沿 Ze 移動。
- Heave：沿 Ye 移動。
- Sway：沿 Xe 移動。

### d.3 相機旋轉

三種旋轉其實也是固定其中一個軸，再旋轉剩下兩個軸構成的平面。

- Roll：固定 Ze，旋轉 Xe、Ye。
- Pitch：固定 Xe，旋轉 Ye、Ze。
- Yaw：固定 Ye，旋轉 Xe、Ze。

假設要旋轉的兩個向量為 A、B，則：

```
A' = cos(θ) × A + sin(θ) × B
B' = −sin(θ) × A + cos(θ) × B
```

每次旋轉 5°，正負號決定旋轉方向。

因為每種旋轉的差別只有要選哪兩個軸，所以直接寫成同一個 `cam_rotate()`，不用為了三種旋轉各寫一個 function。

旋轉後 Xe、Ye、Ze 會跟著改變，focus 及 view up vector 也會在下一次呼叫 `gluLookAt()` 時更新。

### d.4 平行投影（Orthographic Projection）

三個正交相機固定在場景中心 (25, 3, 25) 外 60 單位處，分別沿 x、y、z 軸看向中心。

| 投影方式 | 相機位置 | View up vector |
|---|---|---|
| X 軸投影 | (85, 3, 25) | (0, 1, 0) |
| Y 軸投影 | (25, 63, 25) | (1, 0, 0) |
| Z 軸投影 | (25, 3, 85) | (0, 1, 0) |

Y 軸投影因為是從上往下看，所以不能再拿 y 軸當作 up vector，不然觀看方向會和 up vector 平行。

使用 `glOrtho()` 建立投影矩陣，投影範圍依視窗長寬比調整，避免視窗拉長或縮短時物體跟著變形。

平行投影沒有近大遠小的效果，可以比較方便地觀察物體的大小、相對位置及相機的 view volume。

### d.5 透視投影（Perspective Projection）

使用 `gluPerspective()` 建立投影矩陣。

初始參數如下：

- fovy：90°。
- aspect：視窗寬度 / 視窗高度。
- near plane：1.5。
- far plane：50.0。

相較於平行投影，透視投影會有近大遠小的效果，也比較接近一般遊戲中的畫面。

相機的位置及朝向可以透過前面提到的六種操作自由調整。

### d.6 四分割畫面（Four Viewports）

使用 `style` 記錄目前的投影模式，按下 0～4 即可切換。

四分割模式的配置如下：

| 左上 | 右上 |
|---|---|
| X 軸平行投影 | Y 軸平行投影 |
| Z 軸平行投影 | 透視投影 |

同一幀呼叫四次 `draw_viewport()`，每次透過 `glViewport()` 指定繪圖區域，再分別設定 view matrix 及 projection matrix，最後重畫整棵 scene graph。

四個畫面並沒有各自的 scene graph，而是共用同一棵樹。機器人的動作也只在 timer 中更新一次，不會因為同一幀畫了四次就動得比較快。

這樣可以一邊操作機器人或相機，一邊從其他三個角度觀察變化。

### d.7 世界座標系

直接將世界座標系做成 `world` 底下的節點 `axes`。

- 原點：白色球體。
- X 軸：黃色圓柱。
- Y 軸：紫紅色圓柱。
- Z 軸：青色圓柱。

因為座標軸本身就是 scene graph 的一部分，所以不需要針對每種投影方式另外寫繪製的 function，直接跟著整個場景一起畫即可（之前寫 scene graph 的好處）。

### d.8 View Volume

在三個平行投影畫面中額外畫出透視相機的 view volume，方便觀察相機的位置、方向及觀看範圍。

先將相機的 Xe、Ye、Ze 及 eye 組成一個 4×4 的轉換矩陣：

```
| Xe.x  Ye.x  Ze.x  eye.x |
| Xe.y  Ye.y  Ze.y  eye.y |
| Xe.z  Ye.z  Ze.z  eye.z |
|  0     0     0     1    |
```

使用 `glMultMatrixf()` 將後續繪製的物體從相機局部座標轉換到世界座標。

在相機座標系中，距離相機 d 的平面，其四個頂點為：

```
x = ±d × tan(fovy / 2) × aspect
y = ±d × tan(fovy / 2)
z = −d
```

分別代入 near = 1.5 及 far = 50.0，即可算出兩個矩形的頂點。

使用 `GL_LINE_LOOP` 畫出 near、far 兩個矩形，再使用 `GL_LINES` 從 eye 連接 far plane 的四個頂點，形成金字塔狀的 view volume。

選擇只畫邊線，這樣比較不會擋住場景中的其他物體。

另外也直接重用 `world` 底下的 `axes` 節點，縮小後畫在相機的位置，表示相機自己的座標系。

因為 view volume 是在相機座標系中畫的，所以相機移動或旋轉時只需要更新轉換矩陣，不需要重新計算每個頂點的世界座標。

### d.9 Zoom in / out

兩種投影的 zoom 實作方式不太一樣。

**透視投影：**

- Zoom in：減少 fovy。
- Zoom out：增加 fovy。
- 每次改變 5°，範圍限制在 10°～160°。

fovy 越小，看到的範圍越窄，物體在畫面中也就越大。

**平行投影：**

- Zoom in：縮小 `glOrtho()` 的投影範圍。
- Zoom out：放大 `glOrtho()` 的投影範圍。
- 每次改變 `ortho_r` 2 單位，最小限制為 5。

兩種 zoom 共用同一組按鍵，按下時會同時更新 fovy 及 ortho_r。View volume 也使用同一個 fovy 計算，因此 zoom 時可以在其他畫面中看到錐體跟著變寬或變窄。

### d.10 程式架構調整

這次新增的功能基本上不需要改動原本的機器人及動作系統，主要是在繪圖前多做相機與投影的設定。

另外因為操作的 function 實在太長了，所以拆成兩個：

- `robot_key()`：處理機器人的移動、動作及關節操作。
- `camera_key()`：處理相機的移動、旋轉、投影切換及 zoom。

## e. 心得

還是沒有什麼 fancy idea，沒有啥能自訂義的地方，就普普通通的把功能實作完了。

不過因為上次作業已經把整個場景做成 scene graph 了，所以這次其實省了不少事。像是世界座標軸跟相機座標軸就可以直接共用同一個節點，四分割也只需要換個 viewport 跟矩陣再把整棵樹畫一次。

相機的六種操作原本看起來很多，但實際上就是沿著三個軸移動，或是選兩個軸來旋轉，所以最後只用了兩個 function 處理。

喔但是因為操作的 function 實在太長了，所以這次還把機器人跟相機的操作拆成兩個 function。

還有就是可以用的按鈕越來越少了，再成長下去可能需要引入一些組合鍵或拔掉一些功能了。
